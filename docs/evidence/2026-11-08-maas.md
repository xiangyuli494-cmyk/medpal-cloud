# ModelArts Studio（MaaS）接入侧实测证据（2026-11-08）

> 用途：B8「模型接入」的证据链。结论先说：**代码侧已打通，缺的只是一个有效 API Key**；
> 而 Key 卡在账户侧（余额 0，无法下单按需资源）。这段实测证明「不是我们不会接，是账户不让开」，
> 答辩时可以当场复现下面每一条。

## 1. 端点可达性：MaaS 是独立公网域名，不在 region 端点下

| 请求 | 结果 | 说明 |
| --- | --- | --- |
| `GET https://api.modelarts-maas.com/v1/models`（无鉴权头） | `400 ModelArts.81002` `Failed to get the authorization header` | 域名活的，网关在，先校验鉴权头 |
| `POST https://api.modelarts-maas.com/v1/chat/completions`（假 key） | `401 ModelArts.81003` `Invalid authorization header` | 鉴权层正常工作，只差有效 key |
| `POST https://api.modelarts-maas.com/v1/models` | `404 APIG.0101 method not found` | 该路径只开放 GET |
| `https://modelarts.cn-east-3.myhuaweicloud.com/v1/{pid}/maas/*` | `404 APIGW.0101` | **反例**：不能用 region 端点拼 MaaS 路径 |

DNS：`api.modelarts-maas.com` → `1.95.81.128` / `1.95.59.212`（公网可解析，无需内网打通）。

## 2. 账户侧：为什么拿不到 Key

| 检查项 | 接口 | 实测结果 |
| --- | --- | --- |
| 余额 | `GET https://bss.myhuaweicloud.com/v2/accounts/customer-accounts/balances` | `amount=0` `debt_amount=0` `credit_amount=0` CNY，两个账户（type=1 / type=5）额度全 0 |
| 历史订单 | `GET /v2/orders/customer-orders` | 仅 1 笔 `CS2611021834VX7R8`（CodeArts，`amount_after_discount=0.0`，status=5），无待付账单 |
| 控制台 | ModelArts Studio → 预置服务 → 创建部署（cn-east-3） | 横幅「您的账户已欠费，无法正常购买和使用按需计费云服务」；模型列表「暂无可用模型」 |

余额 0 + 无信用额度 = 无法下单任何按需计费资源；「领取免费额度」按钮也同样走前置校验，点不动。
这不是权限问题，也不是 region 问题，**是账户余额问题**。

## 3. 代码侧：接入只需要 3 个环境变量

`packages/core/medpal_core/llm/openai_compatible.py` 用 httpx 直连（不引 `openai` 包）：

```python
POST {base_url}/chat/completions
Authorization: Bearer {api_key}
{"model": ..., "temperature": 0.0, "messages": [{"role": "system", ...}, {"role": "user", ...}]}
```

所以拿到 Key 之后不需要改一行代码：

```bash
export MEDPAL_LLM=modelarts
export MEDPAL_LLM_BASE_URL=https://api.modelarts-maas.com/v1
export MEDPAL_LLM_MODEL=<该端点上可用的模型名>
export MEDPAL_LLM_API_KEY=<MaaS 的 API Key>
python scripts/smoke_llm.py --strict
```

## 4. 现在能跑出来的证据（无需 Key）

```
$ python scripts/smoke_llm.py
provider = offline
base_url = (空)
model    = (空)
api_key  = (空)
SKIP  模型未配置（MEDPAL_LLM / MEDPAL_LLM_BASE_URL / MEDPAL_LLM_MODEL）

$ MEDPAL_LLM=modelarts MEDPAL_LLM_BASE_URL=https://api.modelarts-maas.com/v1 \
  MEDPAL_LLM_MODEL=fake-key-model MEDPAL_LLM_API_KEY=sk-fake \
  python scripts/smoke_llm.py
provider = modelarts
base_url = https://api.modelarts-maas.com/v1
model    = fake-key-model
api_key  = 已配置
FAIL  调用失败: LLMCallError 模型调用失败: Client error '401 Unauthorized' for url \
'https://api.modelarts-maas.com/v1/chat/completions'
      鉴权被拒：域名是通的，换一个有效 MEDPAL_LLM_API_KEY 即可
```

第二条是**故意失败**的：它证明「链路是通的、请求真的发出去了、服务端也答复了」，
失败只发生在鉴权这一层。这是「接入侧已验证」最硬的证据。

## 5. 对交付的影响（写进方案书的说法）

- 默认 `MEDPAL_LLM=offline`，FakeLLM 让整条决策链、全部测试、全部评测在没有云资源时也能跑完 —— 评委能当场复现。
- 模型是**插槽**不是前置：`/health` 会老实报 `llm_ready=false`，`/v1/cloud` 会点名缺哪几个环境变量，`/v1/ask` 在模型不可用时仍然 200 并在 `conclusion.llm_error` 里写原因。
- 账户充值后，`scripts/smoke_llm.py --strict` 从 FAIL 变 OK，`/health` 的 `llm_ready` 自动变 true，无需改代码、无需重建镜像。

## 6. 复现命令清单

```bash
# 端点活着吗（无鉴权，期望 400 ModelArts.81002）
curl -s https://api.modelarts-maas.com/v1/models

# 鉴权层活着吗（假 key，期望 401 ModelArts.81003）
curl -s -X POST https://api.modelarts-maas.com/v1/chat/completions \
  -H "Authorization: Bearer sk-fake" -H "Content-Type: application/json" \
  -d '{"model":"x","messages":[{"role":"user","content":"hi"}]}'

# 接入侧冒烟（本地，无需 key）
python scripts/smoke_llm.py
```
