# 2026-11-08 真模型接入实测：DeepSeek 官方 API（OpenAI 兼容）

> 相关：[docs/cloud-resources.md](../cloud-resources.md) 第 3 行（ModelArts Studio 探底）、[scripts/smoke_llm.py](../../scripts/smoke_llm.py)、[eval/run_eval.py](../../eval/run_eval.py)

## 0. 一句话

ModelArts Studio 平台侧**没有可调用的对话模型**（模型广场只有盘古 AI4S / 预测 / CV / Embedding 这类**模型资产**，详情页只有「模型介绍 / 版本列表」，没有 endpoint、没有 API Key、没有调用额度；「预置服务」列表为空，顶部写明并发 0 / 调用 0 次每天）。
但这不是「我们没接真模型」——推理层是 **OpenAI 兼容**的，换端点改的是**环境变量，不是代码**。本文记录的就是：真模型接过、跑过、30 条评测指标**一字未变**。

## 1. 配置：三个变量 + 一个 key

| 变量 | 值 |
| --- | --- |
| `MEDPAL_LLM` | `openai`（走 `OpenAICompatibleLLM`，与 `modelarts` / `pangu` / `huawei` 同一个类） |
| `MEDPAL_LLM_BASE_URL` | `https://api.deepseek.com/v1` |
| `MEDPAL_LLM_MODEL` | `deepseek-chat` |
| `MEDPAL_LLM_API_KEY` | 只写本机 `.env.local`（`.gitignore:36` 已挡），本文只留掩码 `sk-2713…0a6bf` |

代码路径：`packages/core/medpal_core/llm/base.py` 的 provider 白名单 `{"openai","modelarts","pangu","huawei"}` 全部返回同一个 `OpenAICompatibleLLM`，只 POST `base_url + "/chat/completions"`。**本次接入零代码改动。**

## 2. 连通性：`smoke_llm.py --strict` 真打了一次

```text
$ python scripts/smoke_llm.py --strict
provider = openai
base_url = https://api.deepseek.com/v1
model    = deepseek-chat
api_key  = 已配置
OK   云端模型可用，返回片段: ok
EXIT=0
```

对照：同一脚本在没 key 时只打印 `SKIP  模型未配置`，`--strict` 下按失败处理（退出码 1）。所以这一行 `OK` 不是占位。

## 3. 30 条评测：换模型，指标不变

同一份数据集 `eval/dataset/v2.jsonl`、同一套检索（BM25）、同一套图谱推理，只换 LLM：

| 指标 | 离线 `--llm offline` | 真模型 `--llm modelarts`（→ DeepSeek） |
| --- | --- | --- |
| dept_acc | 0.933 | **0.933** |
| exam_recall | 1.0 | **1.0** |
| completeness | 1.0 | **1.0** |
| avg_steps | 6.57 | **6.57** |
| zero_evidence | 0 | **0** |
| llm_errors | 0 | **0** |
| avg_ms | 6.9 | 5207.2 |
| llm | `offline->offline` | `modelarts->openai` |

复跑：

```bash
# 离线
bash tools/dev.sh eval
# 真模型（先按 §1 配好 4 个变量，再让脚本读 .env.local）
python eval/run_eval.py --llm modelarts --json /tmp/cloud.json
```

## 4. 这张表说明什么

1. **结论来自图谱推理，不是来自模型。** 30 条里连错的那一条（`反酸烧心该去哪个科？`）都错得一模一样——说明错在检索/词表映射，不在叙述层；换更强的模型不会把它救回来，改词表才会。
2. **模型是可替换件。** 参数量、厂商、是否国产，全被压在一个 `base_url` 后面；华为云有可用对话模型时，改回 `MEDPAL_LLM=modelarts` + MaaS 端点即可，代码不动。
3. **3200 倍延迟差是真实的。** 6.9 ms 是本地 FakeLLM；5.2 s 是单机直连公网模型 + 串行 30 条。演示要不要开真模型，cos 的是「像不像真的」和「会不会卡住」之间的账。

## 5. 边界（别把这张表读过头）

- 只测了**单轮、短问句、串行**；没测并发、长上下文、多轮追问。
- `avg_ms=5207` 是家用宽带直连公网，不代表部署后的响应时间，也不进任何验收门槛。
- 模型负责**叙述**，不做诊断决策；`docs/00` 已写死不输出诊断结论与剂量。
- 若评委要求「必须用华为云大模型」：给的是实测——ModelArts Studio 预置服务为空、并发 0 的截图，以及 `providers/huawei/modelarts.py` 这个插槽本身还在（配置齐了就能切）。**我们是接得上而平台没货，不是接不上。**

## 6. 安全

- key 只在本机 `.env.local`，`git check-ignore -v .env.local` → `.gitignore:36`。
- 本文、PR 描述、issue、任何提交里都**不含明文 key**；日志只打印「已配置 / 未配置」。
- 换 key：改 `.env.local` 一行，重跑 `smoke_llm.py --strict` 即可。
