# 架构与边界

## 1. 分层

~~~text
apps/web            演示页（单文件，无构建）
apps/api            FastAPI：pipeline + 六端点 + seed
────────────────────────────── 依赖方向单向向下
medpal_core
  contracts   协议：Step / Trace / schema.json / validator
  assets      解析 -> 实体 -> 资产卡
  ontology    三元组 / 多跳 / 版本 / 对齐
  retrieval   Retriever 协议 + BM25
  trace       决策链落库 + 报告 + 完整率
  llm         Fake / OpenAI 兼容
  storage     SQLite 连接与路径
  providers   huawei/{obs,gaussdb,modelarts,koosearch}
~~~

## 2. 一次提问发生了什么

~~~text
question
  ├─ 1 retrieve      BM25 在锚点文本上召回 top_k  -> evidence: AST-xxx#anchor
  ├─ 2 entity_extract 词表最长匹配 + 同义词归一     -> ["上腹隐痛","烧心"]
  ├─ 3 std_align     别名表/编码对齐               -> resolved / unresolved
  ├─ 4 kg_query      多跳 BFS，带 provenance       -> paths[{steps[{triple_id,...}]}]
  └─ 5 conclude      规则拼结论（可选挂 LLM 生成叙述）-> evidence: T-xxxxxxxx
                          │
                          └─ write_trace() -> trace 表 + reports/TR-*.md + completeness
~~~

关键点：**第 5 步的 evidence 决定完整率**。写一个不存在的锚点，完整率立刻掉，
报告里那行会标 ❌ —— 这就是「可追溯」的验收方式。

## 3. 为什么 core 里没有 SQL 之外的业务

- 存储只有一处 `storage/db.py`（换 GaussDB 改连接与方言，SQL 语句基本一致）。
- 领域词只在 `data/lexicon/medical.json`（换行业换文件）。
- 结论拼装只在 `apps/api/app/pipeline.py`（换业务换外壳）。

## 4. 边界检查规则

| 规则 | 检查方式 | 失败意味着 |
| --- | --- | --- |
| BND1 core 不依赖 apps | AST 扫 import | 底座被上位应用绑死，不可复用 |
| BND2 云 SDK 只在 providers | AST 扫 import 白名单 | 换云要动全仓 |
| BND3 core 代码无行业术语 | tokenize 去注释/docstring 后扫词表 | 「与行业无关」这句话不成立 |

BND3 的实现细节值得说一句：先用 `tokenize` 抽 NAME/OP/NUMBER 再匹配，
所以 docstring 里写「胃镜」是解释、不违规；写成变量名才违规。

## 5. 失败时怎么表现

- 模型不可用 → 结论仍出，附 `llm_error`，决策链照写。
- 召回为空 → 走本体；本体也无路径 → `gaps` 写明缺口，完整率按「无引用=1.0」记，
  报告里显式标「证据数 0」。
- 云服务未配 → `ProviderNotConfigured` + 缺哪个环境变量。
