# 赛题1 理解与评分对齐

## 1. 赛题原文（校内选拔通知口径）

「基于华为云产品打造 AI 创新应用」：以华为云为承载平台，做出一个有真实场景价值的 AI 应用，
要求讲清用了哪些云服务、为什么用、以及应用本身的创新点与可验证效果。

评审 100 分制（附件 2 的评分细则尚未拿到 xlsx，本表按公开口径 + 往年惯例自拟，
拿到细则后需要回来校准一列权重）。

## 2. 我们的解读：评委到底想看什么

| 评委的疑问 | 我们的回答落点 |
| --- | --- |
| 这是不是又一个套壳聊天机器人？ | 底座有本体与决策链，结论必须指向 `asset_id#anchor`，无证据就标缺口 |
| 云服务是不是贴上去的？ | 五点插槽（模型/存储/对象/检索/计算）都有适配层，环境变量即切换，缺省可离线跑 |
| 有没有可复用价值？ | `packages/core` 通过三条机器可查的边界（B1/B2/B3），换行业只换词表 |
| 效果能量化吗？ | `eval/run_eval.py` 三个指标：科室准确率、检查召回、溯源完整率 |
| 能不能当场复现？ | 离线默认零外部服务，两条命令起服务，30 项测试 |

## 3. 100 分怎么拿（自拟权重，待校准）

| 维度 | 权重 | 我们的动作 |
| --- | --- | --- |
| 创新性 | 30 | 「可追溯」做成可执行契约（schema + 校验器 + 完整率），不是 PPT 概念 |
| 完成度 | 25 | 端到端闭环：入库 → 提问 → 决策链 → 版本快照/差分 |
| 华为云融合度 | 20 | 五服务映射 + 适配层 + 部署脚本；**每条都能指出代码位置** |
| 工程规范 | 15 | 边界检查、禁用语检查、CI、测试、评测脚本 |
| 表达与演示 | 10 | 单文件演示页 + 3 分钟脚本（见 docs/04） |

## 4. 与赛题2、赛题3 的关系

- 赛题2（AgentArts 智能体）：本仓的 core 可作为其工具实现，但**不在本仓提交**。
- 赛题3（ModelEngine Nexent）：团队既有 medpal 仓继续跑，本仓不碰。
- 三线共用一份「资产化 + 可追溯」的方法论，但代码**只复制、不共享目录**，避免一改全崩。

## 5. 明确不做的事

- 不做诊断建议、不给用药剂量、不承诺疗效（禁用语检查会拦）。
- 不接真实患者数据；样本全部合成。
- 不为了「看起来上了云」而写不可运行的云代码 —— 每个 provider 都有 `available()` 与明确报错。
