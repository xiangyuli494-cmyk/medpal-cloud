# 方案书骨架（C4）

> 用途：这是提交材料的**目录级骨架**，不是成稿。每章先写「读者要信什么」，
> 再往下填证据。写作原则：**每个论断后面必须能指到一个文件、一行命令或一次实测**，
> 指不到的论断删掉——评委最烦的就是「我们实现了」后面什么都没有。

- 目标篇幅：正文 12–16 页（不含附录）；每章 800–1500 字。
- 硬约束：不出现诊断结论、不出现剂量、不承诺疗效；样本全部合成数据（LICENSE 已声明）。
- 提交物：方案书 PDF + 演示视频 3 分钟 + 仓库地址（main 分支可复现）。

---

## 1. 摘要（1 页，最后写）

要信的事：这是一个**可追溯的医疗知识底座**，不是一个聊天机器人。

- 三句话版本：把院内散落的诊疗资料变成带锚点的资产 → 用本体推理出决策链 → 每条结论都能点回原文。
- 一切结论都挂在 `asset_id#anchor` 或 `triple_id` 上；挂不上的，进 `gaps` 明说缺什么。
- 云是插槽不是前置：五个插槽（模型/存储/对象/检索/计算）缺任何一个都能离线跑，只报告缺口。
- 关键数字（写完从 `bash tools/dev.sh all` 抄，别手写）：科室准确率、检查召回、溯源完整率、用例数。

## 2. 问题：为什么「答对」还不够

要信的事：医疗场景的失败模式不是答错，是**答了但没人能验**。

- 现状：知识散在 PDF、Word、老系统里，检索给一段文本，谁也不知道它出自哪一版、哪一页。
- 后果：出错无法定位、修订无法传播、责任无法界定——这三件事比「模型准不准」更要命。
- 我们的切入点：把「可追溯」做成**可执行契约**（JSON Schema + 校验器 + 完整率指标），而不是一句承诺。
- 不做的事：不做诊断、不给剂量、不承诺疗效；输出科室与药品名称，用于导诊分流。

## 3. 方案总览

要信的事：三层结构，边界机器可查。

- 资产层：原件 → 解析成锚点（`AST-xxxx#s1.p1.c1`）→ 入库；同一份资料可多次入库，版本可差分。
- 本体层：实体归一 + 三元组（带 provenance 与 confidence）+ 多跳查询 + **冲突体检**。
- 应用层：一次提问产出 6 步决策链，落库、出报告、算完整率；前端三张卡展示结论/链路/缺口。
- 分层纪律：`packages/core` 不 import `apps`（BND1）、云 SDK 只许在 `providers`（BND2）、core 不出现行业词（BND3）。

## 4. 技术实现

要信的事：可追溯不是形容词，是 schema 里 8 个必填字段。

- 契约：`packages/core/medpal_core/contracts/trace/schema.json` 冻结 v1（11 个 op 枚举、8 个必填字段），改它必须 t1 review。
- 链路（6 步）：retrieve → entity_extract → std_align → kg_query → **conflict_check** → conclude，每步带 `inputs / out / evidence / confidence`。
- 完整率公式：`1 - 未解析引用数 / 引用总数`；零引用记 `refusal=true` 单独看待（拒答不该比答错得分高）。
- 冲突不裁决：同一 head + 同一 rel 指向两个 tail 时，只把矛盾连同 `triple_id` 写进 `gaps`，交人判断。
- 换行业：只换 `data/lexicon/*.json` 与 `data/ontology/seed.jsonl`，core 一行不改（BND3 会拦住你）。

## 5. 华为云融合（20 分，逐条对到代码）

要信的事：每一朵云都能被指出**在哪一行被调用**，以及**不配它时系统怎么退化**。

| 插槽 | 服务 | 代码位置 | 不配时 |
| --- | --- | --- | --- |
| 模型 | ModelArts Studio（OpenAI 兼容；华东-上海一） | `providers/huawei/modelarts.py` + `llm/openai_compatible.py` | 规则拼结论，标 `llm_error` |
| 存储 | RDS for PostgreSQL 18（原设计 GaussDB，实测用 RDS 更省） | `providers/huawei/gaussdb.py` + `storage/db.py` | 落本地 SQLite，行为一致 |
| 对象 | OBS（medpal-trace-cn4 / cn-north-4 / 私有桶） | `providers/huawei/obs.py` | 报告写本地 `reports/` |
| 检索 | KooSearch（当前仅到 L0，接口已就位） | `providers/huawei/koosearch.py` | 回落 BM25，评测口径不变 |
| 计算/网关 | CCE + SWR + APIG（演示期） | `Dockerfile` + `deploy/` | 本机 `uvicorn` 两条命令起 |

必写的一段：**为什么 RDS 而不是 GaussDB**——赛题要的是「关系型强一致存储」这个能力，
PostgreSQL 兼容且成本低两个数量级；换回 GaussDB 只改 DSN 与建表方言（`prepare()` 已做 `?`→`%s`）。
诚实写成本：按需 2C4G ¥0.46/h，验证期开 1–2 小时。

必写的第二段：**跨区说明**——ModelArts Studio 在华北四不提供，模型放华东-上海一；
模型是公网 HTTPS + Token，与 OBS/RDS 同区同 VPC 的必要性只存在于后两者之间。

## 6. 可复现的证据（评委最买账的一章）

要信的事：不用信我们，跑三条命令。

- `bash tools/dev.sh all`：ruff → 边界 → 禁用语 → pytest → seed → 冒烟 → 评测，全绿才算过。
- `bash scripts/verify.sh`：7 步打印 PASS/FAIL；`--self-test` 会故意制造 BND1 违规，证明检查真的会失败。
- 评测：`eval/run_eval.py` 输出科室准确率/检查召回/完整率，数据集版本化（v1.jsonl 6 条 → v2 30 条，t2 在做）。
- CI：4 个必绿检查（test 3.11 / test 3.12 / meta / size），PR 必须 1 approve 才能合并，main 禁强推。
- 云侧实测截图与日志：`docs/evidence/`（OBS 桶、RDS 实例、自检输出）。

## 7. 创新点（三条，别写成十条）

要信的事：创新要能落到代码行，落不到就不是创新。

1. **可追溯契约化**：把「有据可查」写进 schema 并让指标下降——不是文档承诺，是合并门禁。
2. **冲突显式化**：本体自相矛盾时不挑一个，而是把矛盾作为结论的一部分输出（第 5 步 conflict_check）。
3. **底座可移植**：三条机器可查的边界 + 五插槽适配层，换行业换云都不动核心；这是「能复用」的工程证明。

## 8. 团队与工程规范（15 分，展示协作不是摆设）

要信的事：三个人真的按流程在跑。

- 分工：t1 底座/契约/方案书，t2 应用与评测，t3 云与交付；CODEOWNERS 按 lane 分路径。
- 流程：分支 `feat|fix|docs|chore/<编号>-<slug>` → PR 标题 `[C2] ...` → 1 approve → t1 合并；单 PR ≤400 行。
- 门禁：ci.yml + pr-check.yml（meta 校验编号、size 校验行数）；保护分支勾选表见 `docs/06`。
- 贴代码：`scripts/setup-branch-protection.sh` 可重放保护配置——不是「我们约定了」，是「一条命令能复原」。

## 9. 局限与下一步（主动认怂，反而加分）

- KooSearch 目前只到 L0（接口就位、实例未联调），所以现在默认 BM25。
- 评测集 6 条样本偏小，30 条版本在扩；指标会掉，掉了照实写。
- ModelArts 跨区；Terraform/一键部署脚本未落地，当前是「手工建资源 + 脚本自检」。
- 冲突只做检测不做消解；多源同一实体的置信度融合留到下一版。

- 3 分钟演示：起服务 → 提问 → 三张卡（结论/链路/缺口）→ 点开锚点看原文 → 制造一次冲突看 gaps。
- 附件：仓库地址、`docs/01-架构.md`、`docs/02-华为云映射.md`、`docs/04-路线图.md`、`docs/evidence/`。
