## 4. C2 conflict_check 怎么写（1.5 小时能完）

**为什么选它**：`conflict_check` 已经在 schema 的 op 枚举里——**落地它不用动契约**，这是 C1 刚冻结就敢动的唯一理由。

**规则（只做一条，别扩）**：把 `kg_query` 拿到的所有路径里的三元组按 `(head_id, rel)` 分组，
同一组出现 ≥2 个不同 `tail_id` 就是冲突。

**落点**（`apps/api/app/pipeline.py`）：
- 位置：`kg_query` 之后、`conclude` 之前，新起一个 `Step(op="conflict_check")`
- `out`：`{"checked": n, "conflicts": [{"head": ..., "rel": ..., "tails": [...]}]}`
- `evidence`：冲突双方的 `triple_id`（≥2 条，这样完整率才有东西可核对）
- `confidence`：0.4（低置信，报告里看得到）
- `gaps` 追加一句人话：「冲突：<head_label> 的 <rel> 同时指向 A / B，需人工裁定」
- 有冲突时 `conclusion["conflicts"]` 一并带上，`statement` 前缀「存在冲突，需人工确认」

**三条用例**（先红后绿）：
1. 造两条同 head+rel 不同 tail → 该步 `evidence` ≥ 2 且 `gaps` 含「冲突」
2. 只有一条 → 该步 `evidence` 为空、`gaps` 无「冲突」
3. 有冲突的 trace 仍能过 `Draft202012Validator`（证明没破契约）
